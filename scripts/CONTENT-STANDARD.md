# 内容标准 v2（CONTENT-STANDARD）

> 本文件定义站点的**作者身份、读者分层与质量红线**。所有新增/改写页面的工作（人或 AI）都必须遵循它，
> 并由 `tests/regression.mjs` 的「内容质量」检查项强制校验。

---

## 一、作者身份（Persona）

写作时的固定身份设定（可用作提示词开头）：

> 你是**前省队/国家队陪练出身的技术与体能双线教练**，退役后取得 **NSCA CSCS** 认证，并有 8 年一线教学与康复转介经验。
> 你带过三种人：刚拿拍的成年人、每周打 3 次的业余高手、以及冲省赛/职业的青年选手。
> 你的特点：
> 1. **先给结论和可执行动作，再讲原理**——读者没耐心听 500 字铺垫。
> 2. **说人话**：术语第一次出现必须有一句白话解释（与 `docs-simple.js` 术语词典一致）。
> 3. **分层开方**：同一动作/能力，基础、进阶、精英三档的参数与判断标准必须分别写明，不让任何一档读者"吃不饱"或"吃不下"。
> 4. **敢下判断**：给出"什么时候该停、什么时候可以加"的明确阈值，而不是"因人而异"。
> 5. **不编造**：只使用公认的训练学参数与常识性生理机制；不虚构研究数据、不写"某研究表明"这类无出处表述。

---

## 二、读者分层（每一档都要"够用"）

| 代号 | 人群 | 他们最想要 | 页面必须提供 |
|---|---|---|---|
| **B 基础** | 零基础 / 打球＜1 年 / 每周 ≤2 次 | 今天练什么、做几组、别受伤 | 最小可行动作、次数/组数、常见错误图示级描述、安全边界 |
| **I 进阶** | 打球 1-3 年 / 每周 3-4 次 / 打业余比赛 | 怎么突破瓶颈、如何评估进步 | 渐进负荷方案、评估指标与阈值、周期安排、错误→原因→纠正 |
| **E 精英** | 半专业以上 / 每周 ≥5 次 / 有教练或团队 | 细节与边际收益、个体化调整 | 更高阶参数（速度/功率/节奏）、比赛期减量与峰值、监控指标、伤病风险与替代方案、可自我校准的测试协议 |

**判定标准：一篇页面合格的最低要求 = 三档读者都能在页面里找到"下一步该做什么"，而不只是"应该做什么"。**

## 三、每篇页面的必备结构（质量红线）

升级后的页面（`<head>` 内含 `<!-- quality:v2 -->` 标记）必须包含以下区块；缺一即回归测试失败。

1. **一句话结论区**（页面开头，h1 之后）：用 `.callout` 给出本篇最核心的一条可执行结论。
2. **分层处方**（h2 标题含「分层处方」）：`.rx-grid` 内三档并列（`.rx.rx-base` / `.rx.rx-mid` / `.rx.rx-elite`）。
   每张卡片必须**各自**写全下面六个维度（机器逐卡检查，缺一即失败；只写在别档不算）：

   | 维度 | 写法示例 | 机器判定（任一命中） |
   |---|---|---|
   | 动作/剂量 | `每个动作 3 组 × 8 次`、`多球 6 组 × 20 球`、`测试：单腿下蹲 5 次` | `组 ×` / `× 数字` / `动作：` / `测试：` / `练习：` / `多球` / `回合` |
   | 强度 | `70-80% 1RM`、`RPE 7`、`RIR 2`、`心率 3 区`、`发力 8 成` | `% 1RM` / `RPE n` / `RIR n` / `心率 n 区` / `HRmax` / `发力 n` / `速度 n` / `负重` |
   | 频率 | `每周 3-4 次`、`每周固定 2 场对抗` | `每周 n …` / `每 n 周` / `每天 n …` / `频次：` |
   | 恢复 | `同部位间隔 ≥48 小时`、`组间休息 90 秒` | `间隔` / `休息` / `≥ n 小时` / `≥ n 天` |
   | 时长上限 | `单次 ≤90 分钟`、`单次训练总组数上限 18-20 组` | `≤ n 分钟` / `上限` / `不超过 n 分钟` / `单次 ≤` |
   | 进阶触发 | `连续 2 次在 RPE 7 下完成 → 加 5%` | `触发` / `进阶` / `达标` / `通过标准` |

   - 徽章（`.rx-badge`）里写了「每周 N 次」时，卡片内「每周 N 次/场/课」口径的频次必须有一个与徽章数字相差 ≤1（避免徽章与正文互相打脸）；
   - 评估、筛查、装备、康复类页面的「强度」用该页合适的量化口径（测试用力程度、疼痛 ≤n/10、负荷 %、磅数区间等），不要把训练学口径硬套上去。
3. **自测与进阶标准**（h2 标题含「自测」）：一张表，含「测试动作 / 通过标准（数字）/ 不达标时的退阶」。
4. **错误 → 原因 → 纠正**：至少 3 组，写成表格或列表；错误描述要能被自己录像对照。
5. **精英细节**（h2 标题含「精英细节」）：≥5 条，属于"同样动作，高手多做什么"的边际收益项（时机、节奏、预判、个体化、比赛期处理等）。
6. **安全与适用边界**：一条 `.callout`，写明禁忌情形与就医/找教练的信号。
7. **依据说明**：一条 `.callout`，写明本篇参数来源类型（NSCA CSCS 训练学框架 / 运动生理常识 / 项目惯例），**不得虚构文献**。

### 参数密度要求
每篇 ≥ **8 处**带单位的量化参数（如 `3 组 × 8 次`、`70-80% 1RM`、`RPE 7`、`RIR 2`、`≥48 小时`、`心率 2 区 60-70%`、`30 秒`）。

### 文风要求
- 教练口吻、第二人称；句子短；先动作后原理。
- 每段不超过 4 行；避免"应该注意"这类空话，改成"如果你 X，就做 Y"。
- 页内不超过 3 个感叹号，不使用夸张营销词（"史上最强""必看"）。
- 术语首次出现附白话（小白模式会自动加气泡，正文仍需可独立理解）。

### 禁止项
- 虚构研究结论、编造百分比（如"研究表明提升 37%"）。
- 只给原则不给参数。
- 只服务一档读者（例如通篇精英向，或通篇"因人而异"）。
- 复制粘贴其它页面内容而不做项目化改写。

## 五、验收方式

```bash
node tests/regression.mjs                          # 结构/链接/区块/参数密度/全站覆盖（CI 门禁）
node scripts/review-content.mjs                    # 逐档语义审稿：三档卡片是否各写全六个维度
node scripts/review-content.mjs --detail 页面.html  # 带上下文：把被点名卡片的现有正文打出来
```

- 任何被标记 `<!-- quality:v2 -->` 的页面都必须通过全部内容检查；
- **全站覆盖**：`docs/*.html` 里除「豁免清单」外的每一页都必须打标记；豁免清单写死在
  `tests/regression.mjs` 的 `V2_EXEMPT`（当前只有 `40-search.html` 这类正文由 JS 动态渲染的纯功能入口页），
  并在本节备案。新增文章页却忘了打标记，回归会直接失败；豁免页若已达标但仍在清单里，同样失败。
- `scripts/review-content.mjs` 是**逐档语义**检查（比回归更细）：它会把每张 `.rx` 卡片的纯文本拎出来，
  逐张核对「动作/剂量、强度、频率、恢复、时长上限、进阶触发」六个维度，并比对徽章与卡片频次是否自相矛盾。
  它不能替代人读，但能把「只给原则不给参数」这类问题挡住。
- CI 侧：`.github/workflows/quality.yml` 在 push / PR 时跑上面的命令；`deploy.yml` 的部署任务依赖质量门禁，
  红灯时**不会**上线。
